# Customer Outreach Propensity Scoring

An evidence-backed, end-to-end propensity-scoring prototype that prioritises customers for re-engagement outreach. It demonstrates production-oriented modelling controls using public data; it does **not** claim to be a live B2B CRM deployment.

## Business decision

Given limited outreach capacity, which eligible customers should be contacted first because they are most likely to make a purchase in the next 28 days?

The output is a ranked queue with a probability score, priority band, operational action, and concise reason.

## Evidence and data source

The model uses the UCI Online Retail dataset: 541,909 transaction records from a UK non-store retailer between 1 December 2010 and 9 December 2011. It is public data, cited as Chen, D. (2015). *Online Retail* [Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C5BW33. CC BY 4.0.

This is a retail re-engagement use case. It demonstrates the same scoring-pipeline principles used in CRM or outbound workflows, but is not presented as B2B CRM data.

## Point-in-time model design

- **Scoring entity:** customer.
- **Lookback:** the 90 days before the score date.
- **Target:** at least one positive sale in the next 28 days.
- **Validation:** the final eight weekly score snapshots are held out chronologically.
- **Model:** logistic regression with numeric imputation/scaling and one-hot encoded country.
- **Commercial evaluation:** conversion base rate, ROC-AUC, average precision, Brier score, precision in the top decile, and lift versus the base rate.

The model excludes all outcome-period purchases and post-score transaction data. This is the key control against temporal leakage.

## Observed holdout evidence

The included `outputs/metrics.json` was generated by running `train_model.py` against the cited source, before publication.

| Check | Held-out result |
| --- | ---: |
| Training customer-snapshots | 54,765 |
| Chronological test customer-snapshots | 18,076 |
| Test cutoff | 20 September 2011 |
| Test conversion base rate | 38.0% |
| ROC-AUC | 0.687 |
| Average precision | 0.621 |
| Brier score | 0.211 |
| Precision in top 10% | 81.4% |
| Top-decile lift versus base rate | 2.14× |

Interpretation: within this historical retail dataset, the highest-ranked tenth of eligible customers converted at roughly 2.14 times the overall held-out rate. This is **ranking evidence**, not causal proof that sending a message creates the sale; a live deployment should test incremental uplift with a randomised holdout.

## Data-quality rules

- Keep only product-like SKUs; remove postage, adjustments, and service rows.
- Keep positive quantity/positive price lines as sales.
- Use negative quantity product lines as returns.
- Score only customer records with an observed ID.
- Preserve raw transaction data outside the repository; the repository contains derived evidence and code.

## Run locally

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe train_model.py
.\.venv\Scripts\streamlit.exe run app.py
```

By default, `train_model.py` expects the UCI file at `../../data/uci_online_retail/Online Retail.xlsx` relative to this project. Set `RETAIL_DATA_PATH` if you store it elsewhere.

## Output contract

The scored queue contains:

- `CustomerID`
- `score_date`
- `propensity_score`
- `priority_band`
- `recommended_action`
- recent purchase and returns features
- `score_reason`

## Proposed CRM/GCP deployment

```text
CRM / activity sources → BigQuery feature table → data-quality checks
→ Vertex AI training and model registry → scheduled batch scoring
→ BigQuery scored queue → CRM / SDR workflow → monitored outcomes
```

This architecture is proposed, not deployed in this portfolio project.

## What the prototype proves

- Reproducible training and scoring pipeline.
- Time-aware target and validation design.
- Human-actionable prioritised output.
- Explicit separation between evidence, assumptions, and deployment proposal.

## What it does not prove

- Live B2B performance.
- GCP deployment, CRM integration, or actual SDR uplift.
- Identity resolution or marketing-consent compliance for a real customer database.
